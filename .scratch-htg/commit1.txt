Map the 26.1 GUI extraction wave back onto 1.21.11

The 1.21.11 node now compiles from the shared source, so every rename the 26.1
release made to the GUI drawing API is expressed once here instead of at the
~200 call sites it would otherwise touch:

  GuiGraphics       -> GuiGraphicsExtractor   (class, in a new package)
  graphics.text(    -> graphics.drawString(
  extractRenderState(  -> render(
  extractBackground(   -> renderBackground(
  ...renderer.state.gui.GuiElementRenderState
                    -> ...gui.render.state.GuiElementRenderState

The rules are four-argument regex replacements with the reverse pinned to a
token that appears nowhere in the source, which makes each one strictly
one-directional. That shape is not stylistic. A two-argument string replacement
records a canonical spelling and an alias and lets Stonecutter apply the pair in
either direction -- so a rule declared for the old nodes is also live, reversed,
on the new ones. Writing such a rule the other way round does not merely fail to
help, it rewrites the new nodes' correct code back into the old spelling: an
earlier attempt broke all three 26.x nodes exactly that way. The same symmetry is
why GuiGraphics and GuiGraphicsExtractor cannot be paired as strings at all --
the one is a prefix of the other, so the reverse direction fires on the 26.x
nodes' genuine GuiGraphics. An explicit inert reverse removes both hazards.

The XaeroBufferProvider rule is converted to the same four-argument form for
consistency; its behaviour is unchanged.
